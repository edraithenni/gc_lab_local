# Local Ray + PyTorch MPS на macOS

Этот каталог — самостоятельная копия Python-проекта из рефакторинговой версии с добавленным PGC-FR. Kind/Kubernetes/Docker не нужны. Для локального запуска скопируйте каталог целиком и установите зависимости в arm64 Python 3.11.

## Запуск

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-local.txt
python -c 'import platform, torch; print(platform.machine(), torch.backends.mps.is_available())'
```

Для CIFAR-10 перенесите каталог из исходного репозитория `gc_lab_v1/data/cifar10` в `data/cifar10` внутри этого проекта. Датасет должен содержать стандартный `cifar-10-batches-py`.

```bash
./run_local.sh
```

Dashboard: http://127.0.0.1:8265. Остановка: Ctrl+C, при необходимости `ray stop --force`.
Результаты: `data/results/<scheme>-<timestamp>-<id>/`.

## Подбор конфигураций

`local.env` — файл конфигурации запуска. Для быстрого первого теста по умолчанию 3 работника, PGC-CR, 2400 примеров, 1 эпоха. Для PGC-FR при s=1 установите:

```dotenv
GC_SCHEME=pgc_fr
NUM_WORKERS=6
NUM_PARTITIONS=6
TRAIN_LIMIT=2400
BATCH_SIZE=40
```

При `n=6,s=1,m=2` все пять схем допустимы; для продолжительного обучения можно увеличить `TRAIN_LIMIT=9600` и `EPOCHS=100`.

Если MPS не работает, установите `GC_DEVICE=cpu`. Все работники локального Ray на GPU используют **один физический GPU**, Ray не создаёт отдельного GPU на работника. Шесть одновременно работающих ResNet-18 на MPS могут привести к конкуренции за вычисления и память. Производительность не будет эквивалентна многоузловому кластеру.

## Отличия от исходной версии

- `app/train_ray.py` запускает локальный Ray через `ray.init(address="local")`, объявляет CPU и специальные ресурсы планирования для акторов.
- `app/worker.py` создаёт PyTorch-модель на устройстве `GC_DEVICE`; мини-пакеты переносятся на устройство, а закодированное сообщение возвращается в CPU для безопасной передачи через Ray. `num_cpus=1` на работника.
- `app/parameter_server.py` создаёт уникальную папку результатов каждого запуска. Остальная логика SGD и EMA оставлена без изменений.
- `app/coding/` содержит пять схем; математическая часть сохранена из ранее подготовленного рефакторинга и дополнения PGC-FR.

Важное ограничение: оценка `train_loss` по сообщениям работников не является сопоставимой между всеми схемами; ориентируйтесь на `test_accuracy`, `test_loss`, время эпох и ответы работников. MPS может вызывать синхронизацию при пересылке тензоров обратно на CPU. Это именно функциональный локальный вариант, не средство моделирования физических отказов сети.

Python-запуск с Ray и MPS на реальном Mac не мог быть выполнен в среде подготовки; тесты схем можно прогнать через `python tests/test_schemes.py` и `python tests/test_pgc_fr.py`.
